# 顾客购买记录与商家自动记账

## 顾客端

店铺导航新增“我的购买记录”，地址为 `/shop/:slug/account`。顾客可以继续访客下单；登录并验证邮箱后下的新订单自动绑定当前顾客账号。顾客会话使用单独的浏览器存储键，不覆盖商家或平台会话，也不会调用商家 Dashboard 初始化店铺。

账号统计此店铺的全部关联订单：已付款消费、已购买件数、已退款金额、待付款订单。待付款、取消和已全额退款订单不计入有效消费及购买件数。列表最多显示最近200笔，总额不从这200笔简单相加。数据在进入页面、回到窗口及可见页面每30秒读取并更新。

访客旧订单需要订单编号、专属查询凭证，并且订单邮箱与当前账号已验证邮箱一致才能关联。不能只填写邮箱或手机号检索他人订单。已被其他账号关联的订单不能被重新认领。查询凭证不出现在网址中；顾客退出或会话失效时清除当前标签页保存的订单查询凭证。

顾客注册、邮箱验证及找回密码使用现有 Supabase Auth。应用不会伪造验证完成，也没有接入新的外部邮件服务。**发布前请在 Supabase Authentication → URL Configuration 的 Redirect URLs 中允许实际网站的顾客账号回调路径**，例如 `https://你的域名/应用路径/shop/**`；不要添加不属于你的域名。GitHub Pages 的应用路径包含仓库名。客户验证/找回密码链接须回到 `/shop/:slug/account`，不能只允许商家根目录。前端会生成当前应用域名内的回调地址。

## 商家端

所有者新增“收支与利润”菜单。有效试用或订阅内可以查看和记账，其他店铺及团队普通角色不能读取账本。新增商品和编辑商品时，所有者及经理可填写单位成本；库存角色不显示成本。成本可留空，留空表示未知，不能按零成本计算利润。

每笔新订单保留成交时的商品成本。修改商品当前成本不改变历史订单成本。订单确认收款、全额退款、佣金实际提现后，数据库触发器自动写入一次对应记录，不依赖前端是否打开页面，也不因重复确认或重复支付回调而重记。银行、电子钱包、USDT、商家自有收款链接仍由商家先核对真实到账，确认状态后才自动入账，系统不会通过填写账号猜测到账。

商家只需录入系统无法获知的日常费用、实际邮费、广告费、手续费等。手工记录有请求幂等保护；错误记录可以填写原因后作废，保留审计记录，不能删除自动订单事件。不得重复手工录入已自动记录的订单收入、退款或佣金。

页面区分现金流水与利润：

- 现金结余 = 订单收款 + 手工收入 − 退款 − 实际佣金提现 − 手工支出。
- 利润估算 = 订单收款 − 退款 − 已售商品成本 − 订单佣金 + 其他经营收入 − 经营费用。
- 进货付款只影响现金流，实际商品成本通过成交快照计入利润；投入资金不当作经营利润。
- 全额退款且退回库存时，恢复该订单对应销售成本；不退货时保留成本。
- 只要符合筛选条件的订单缺少必要成本，就显示“待补成本”，不会显示虚高利润。

按马来西亚时间提供全部、按月及按日统计。汇总覆盖全部符合条件的记录，流水列表最多显示最近200笔。历史订单没有真实收款时间时保留未知，不把下单时间当作到账时间；日期筛选明确排除未知记录并提示数量。商家可凭真实凭据补录历史日期及修正订单成本，须填写更正原因，版本校验防止覆盖另一窗口刚更新的数据。利润是按已录入资料的经营估算，不是银行余额或已完成税务申报。

## 升级及验证

012 增加顾客订单归属和受控查询入口；013 增加商品成本快照、账本表、自动事件触发器和所有者接口。升级包现包含005–013，已经存在的迁移由守卫跳过；先审查备份再运行后端 `upgrade-and-deploy`，之后发布前端。本次没有自动执行正式迁移或发送真实邮件、创建真实付款。

源码测试使用隔离 PostgreSQL 验证：顾客跨账号隔离、邮箱与凭证关联、结账重试不改归属、成本不公开、成本快照、幂等收支、作废审计、进货/投入不重复计利润、退款联动、未知历史日期、马来西亚日期边界、到期权限。浏览器用模拟账号验证独立会话、跨设备统计、退出清理、成本补录、费用及手机页面。实际邮箱验证和真实商家账目仍需部署后验收。
