# 免费方案加密备份

不需要升级 Supabase 方案。GitHub Actions 执行及 Artifact 存储仍受 GitHub 账号额度限制；本项目不购买额外额度。首次先手动执行，确认下载成功后再启用定时备份。

## 先保存两个 Repository Secrets

在 GitHub 仓库 Settings → Secrets and variables → Actions → Secrets 中新增：

| 名称 | 填写内容 |
| --- | --- |
| `SUPABASE_BACKUP_DB_URL` | Supabase 项目 Connect 中的 Session pooler 完整数据库连接串，使用端口5432；密码必须正确编码。必须是现有 ezshop 项目，不能使用6543事务池连接。 |
| `BACKUP_ENCRYPTION_PASSPHRASE` | 至少24个字符的独立随机备份密码，建议密码管理器生成32字符以上。请另存密码管理器；GitHub 保存后不会再显示原值，丢失后无法解密。 |

现有 Repository Variables `SUPABASE_PROJECT_REF`、`VITE_SUPABASE_URL` 沿用，不需要重新创建。不要把连接串、密码、解密后的资料发到聊天或提交代码。这个工具不会读取、重置或更换数据库密码。

## 手动备份

打开 Actions → EZShop · 加密数据库与图片备份 → Run workflow，分支main。

任务只读连接数据库，下载 ezshop-media 中的公开图片，生成认证加密文件并完成解密回读。默认不会修改或恢复数据库，也不会停止网站。若图片清单在备份期间改变，会失败并要求低流量时重试，不把不完整备份当作成功。

成功后，在该次任务底部 Artifacts 下载 `ezshop-encrypted-backup-…`。其中只有 `.ezbackup` 加密文件。Artifact **7天后自动删除**，请及时下载并另存安全位置。加密密码另行保存。任务失败时不会上传未验证的文件；日志不显示连接串、原始资料或密码。

## 备份范围和限制

- 数据库：ezshop/public/auth/storage 四个schema的自定义格式归档。包括账号资料和权限信息，必须保密；不丢弃ACL，以便恢复后保留受控函数权限。
- 图片：ezshop-media bucket的真实文件和名称映射、大小及SHA-256；其他bucket、商家外部HTTPS图片不包含。
- 不包含：Edge Secrets、项目配置、第三方账户、DNS、Storage其他bucket。它不是整个Supabase项目的一键克隆。
- 单次数据库和图片总量上限512MiB，图片单文件上限10MiB，超过会失败，不静默截断。
- 数据库快照与Storage是两套服务。工具比对导出前后的图片元数据，不能承诺跨服务完全原子快照。大型或高并发商家须采用适当的正式备份方案。
- PostgreSQL客户端使用官方postgres:18镜像、TLS证书校验和只读会话；连接失败时不要关闭TLS校验。

## 自动备份

首次手动备份下载且确认密码保存后，可在Repository Variables设置 `EZSHOP_BACKUP_SCHEDULE_ENABLED` 为 `true`。

随后每日马来西亚时间02:20触发，GitHub可能延迟执行。保留期仍为7天。请监看失败任务，并定期将文件另存长期位置。仅开启开关不能证明备份已产生，须查看实际任务结果。删除该变量或改为false会停止定时备份。

## 解密与恢复核对

使用Node 24，保留仓库中的解密脚本。在私有电脑或独立测试环境，将备份密码放入 `BACKUP_ENCRYPTION_PASSPHRASE` 环境变量，然后运行：

```sh
node scripts/decrypt-backup.mjs downloaded.ezbackup restored.tar.gz
```

脚本拒绝覆盖已有输出，错误密码或篡改会失败。解密后的归档包含 `database.dump`、`manifest.json` 和图片文件目录；图片原名称见manifest映射。不要上传解密文件至GitHub或公开网盘。

**解密回读、pg_restore --list都不等于正式恢复成功。** 真实演练必须使用独立测试项目，并核对资料数量、权限、登录和图片读取。恢复到不同项目时，还要审查图片URL原项目域名到目标域名的转换，并重新配置服务密钥；不能只恢复数据库就认定所有图片和Stripe都已接通。测试项目不能连接正式Stripe自动扣款。Supabase已有的auth/storage结构、角色及版本需要审查，不能对正式项目盲目运行清库或恢复命令。这个仓库不提供自动覆盖生产数据库的工作流。

本地测试 `node tests/postgres_backup_restore.mjs` 只创建临时PostgreSQL容器，验证四个schema导出、加密解密、关系资料、图片字节、ACL及RLS恢复，结束后清理。它不连接Supabase，不能代替你的实际备份及恢复演练。
