# EZShop 后端升级及平台收款

当前源码可继续通过 GitHub Actions 操作。推送源码不会自动修改 Supabase、发布网站、转账或发送邮件。

## 已确认的实际情况

2026-11-05 实现本次功能时的只读检查：Supabase 基础健康接口返回 `ok: true`；支付 RPC 返回 `PGRST202`；payments、stripe-webhook、translate-content、send-notifications 四个函数均返回 404。环境没有 Supabase 管理令牌、Stripe API 密钥、Resend 或 Google 翻译密钥。GitHub Actions 状态 API 在当前环境返回 Forbidden，因此不能宣称已经看见远端构建/发布成功。

## 已有 001–004 项目的受控升级

`supabase/upgrade-after-004.sql` 包含 005–010，执行前先审查并备份数据库及图片。脚本检查已有 004 结构，跳过已存在的 RPC 链，在一个事务中应用缺少的部分，不重复初始化旧表，不操作已有订单金额，不设置真实收款资料或自动授予管理员。最后刷新 PostgREST 缓存并输出安全结构检查结果。

此升级已经在隔离 PostgreSQL 中验证：从 004 升级、已有业务资料保留、重复执行不破坏 RPC 链、内部入口仍对浏览器关闭。它不能替代实际项目备份与恢复演练。

### 方法一：Supabase SQL Editor

复制 `supabase/upgrade-after-004.sql` 到你的项目 SQL Editor，核对项目后执行。已完成 005/006/007 也可以使用此文件，脚本会保留已存在的入口。遇到前提或权限检查失败时停止，不要删表或强行跳过错误。

### 方法二：GitHub Actions

1. 仓库 Settings → Secrets and variables → Actions：添加 **Secret** `SUPABASE_ACCESS_TOKEN`。这是 Supabase 账号管理令牌，不是 anon key、数据库密码或 service role key。
2. 标准 Supabase 项目的编号会从公开 URL 自动识别；也可用 **Variable** `SUPABASE_PROJECT_REF` 明确指定。公开的 `VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY` 沿用已有设置。URL 必须与待升级项目相符。
3. 确认已有可用备份并审查升级文件。
4. Actions → **EZShop · 后端检查与手动升级**，选择 `upgrade-and-deploy`，输入 `UPGRADE_AND_DEPLOY` 后运行。
5. 工作流先运行测试、检查升级包一致性和已有结构，再执行事务、检查数据库、保存服务配置并部署函数。只选择 `check` 则仅检查，不改数据、不发送邮件、不付款。如果已在 SQL Editor 完成升级，可选择 `deploy-functions` 并输入 `DEPLOY_FUNCTIONS`，不会再调用管理接口执行 SQL。

脚本不使用 `supabase db push` 盲目重跑手工迁移。固定使用 CLI 3.0.0，已核对该版本使用 `--remote`、`--use-api` 参数。此工作流未在真实项目执行；管理令牌必须有目标项目的数据库和 Edge Functions 权限。

## 平台收款与商家商品款

用户指定的 Hong Leong Bank、TNG、USDT/TRC20 及 Stripe 自填金额链接用于 **EZShop 平台向商家收服务费**。真实账户资料不在此仓库中；私有配置草稿单独保存在当前工作区的受限目录，尚未远端执行。它们不能默认代替每家商店的顾客商品收款账户。

平台后台提供收款设置及订阅审核。只有平台管理员可以保存配置、查看申请队列和审核；普通商家仅查看自己的申请与付款指示。TNG 须核对收款人及钱包号码/真实二维码，系统不伪造二维码。TRC20 地址验证 Base58Check 校验和，只显示用户指定的 TRON 网络。

Stripe Payment Link 是自填金额入口，不能视为固定月费或自动续费凭证。流程为：商家输入申请金额 → 查看平台付款指示 → 完成外部付款 → 提交真实参考号/交易哈希 → 管理员核对银行、钱包或 Stripe 实际到账 → 输入实际金额、实际参考号及开通天数。提交资料不会改变 Pro 权限；审核开通、拒绝和期限有记录。相同实际付款参考号不能重复批准。到期在受保护 API 访问时核对并恢复 Free；仍有效的 Stripe 自动订阅或人工授权互相保留，不会因为另一种支付来源取消而错误撤销服务。

USDT 申请金额以 USDT 表示，不伪装成 MYR，也不使用虚构汇率。系统不代用户签名、转账或自动认定交易哈希已确认。管理员须核对实际代币、收款地址、金额和链上状态。付款金额可自填时，开通期限由平台管理员明确确认，没有后台偷偷采用固定月费。

## 可选服务配置

可在 Supabase 后端安全配置中设置，也可用同名 GitHub **Secrets** 由升级工作流写入。未提供的可选值保持 Supabase 已有设置；缺少服务配置时功能明确失败，不会伪造成功。

| 配置 | 用途 |
| --- | --- |
| Variable `APP_URL` | 实际网站根地址，包含仓库路径；未提供时使用当前仓库的标准 Pages 根地址 |
| `STRIPE_SECRET_KEY` | 商品自动付款及 Stripe Connect 的平台 API 配置；公开 Payment Link 不能替代此密钥 |
| `STRIPE_WEBHOOK_SECRET`、`STRIPE_CONNECT_WEBHOOK_SECRET` | 平台订阅及商家收款事件验签 |
| `STRIPE_PRO_PRICE_ID` | 仅在以后启用固定周期自动订阅时需要；自填金额人工审核流程不需要伪造价格 ID |
| `RESEND_API_KEY`、`MAIL_FROM` | 已验证的 Resend 发件身份及邮件发送 |
| `NOTIFICATION_JOB_SECRET` | 高熵独立通知任务密钥 |

平台收款配置好后，可以使用人工审核服务费流程；这不等于商品自动付款、Resend 投递已配置。所有服务密钥均不得放进 `VITE_` 变量。

## 通知任务及实际验证

收据和提醒采用顾客订单语言，并使用成交时商品译文。模板转义 HTML，服务商接受只记录为接受，不等同客户收到。**EZShop · 通知发送任务** 手动输入 `SEND_NOTIFICATIONS` 才会实际发送队列消息。

定时执行默认关闭。只有明确设置 Repository Variable `EZSHOP_EMAIL_DISPATCH_ENABLED=true` 后才每 15 分钟尝试处理队列。未配置密钥时停止，不发送。首次启用前，使用受控测试订单和测试邮箱验证实际投递，再决定是否启用自动任务。

`npm run check:live` 为只读检查。它能检查数据库结构、安全入口与函数可达性；`production_verified` 固定为 false，因为脚本不会冒充真实付款、邮箱投递、备份恢复、安全审计或商家 KYC 已通过。各项实际验收仍须记录。

后端通过验收后，再用既有 **EZShop · 手动发布网站** 工作流发布前端。后端升级工作流不会自动发布正式网站。


## 私有收款配置

真实收款资料和管理员引导保存在当前工作区的私有 SQL 文件，不属于公开升级包，也不会由 GitHub 工作流自动上传。执行前核对其中的登录邮箱是你自己的已验证商家账号，确认收款资料及 Stripe 币种；它只对该账号授予平台管理员，不创建账号、不向其他商家分配权限。币种未确认时，Stripe 链接保持关闭。请勿把这个私有文件提交到公开仓库。

## 三端独立入口

顾客使用 `/shop/:slug`，商家使用 `/merchant`，平台管理员使用 `/platform`。路径均加在实际网站根地址之后（GitHub Pages 包含仓库路径）。原根地址自动进入商家端并保留付款返回参数及邮箱验证片段。平台端有自己的登录页及布局，只提供中英文，不出现在商家导航或顾客页面。直接访问平台地址仍须通过后端管理员权限验证；平台端不调用会初始化商家的 dashboard 接口。商家自己的平台服务费申请继续保留在商家收款与订阅页。认证和数据库继续复用现有 Supabase，未拆成三个数据库或部署站点。此修改仅需更新前端，不需要重复运行 SQL。

## 当前开发范围

自动翻译已移除；六语界面、人工维护各语言商品内容继续保留。Stripe 自动支付与自动订阅按用户要求最后接入，不作为当前人工收款版本的可用入口。平台现有 Stripe 自填金额链接仍仅用于平台服务费人工核款。邮件服务需要实际发件域名及服务商配置后才能验收，未提供时不能宣称已投递。

## 顾客主动查询订单

各店铺提供 `/shop/:slug/track` 查询入口。下单后的结果页可下载包含店铺查询网址、订单编号和专属查询凭证的私有文本文件。换设备时输入订单编号与凭证，后端同时核验店铺归属；凭证不放在网址或日志中。无法查询时不区分订单不存在和凭证错误。凭证丢失须联系商家核实身份，不开放仅凭邮箱、电话或订单号查询。订单状态和已登记运单来自真实订单，未收款时不显示付款成功。

邮件服务按用户要求暂缓，不需要配置 Resend；当前先使用站内查询。自动收据及提醒尚未启用，不作为已投递功能宣传。

## 七天试用及 Stripe 月订阅更新

当前升级包新增 010，需再次审查并备份后执行 upgrade-and-deploy；已存在的 005–009 会跳过。010 只增加固定试用截止、续费限制及权限入口，不删除业务资料。已有商家从迁移时获得七天过渡期；重复执行不延长。仅发布前端不会启用这些后端限制。Stripe 月费已确认 MYR 99.90，外加 6% 税为 MYR 105.89；先配置并验证测试密钥、月费价格、外加税率及 Webhook，最后打开前端 Stripe 开关。未升级试用配置时，自动订阅入口拒绝扣款，避免遗漏七天试用。
