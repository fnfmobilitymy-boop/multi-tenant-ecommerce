# 人工收款上线核对

当前不接支付网关；平台Pro和商品货款分别人工核款。自动记账、库存处理与批量打印仍保留。此文件是操作指南，不是已经完成正式验收的证明。

## 商家设置

1. 在自己的商家后台确认国家和币种，上传店铺及商品图片，填写商品价格、单位成本和库存。没有成本时利润可能显示待补，系统不会把未知成本当作零。
2. 在“收款与订阅”填写自己的银行、电子钱包或USDT等收款资料。商品款付给商家，不能把其他商家的货款导入平台订阅账户。USDT须核对网络；系统不自动换汇或确认链上到账。
3. 在“店铺设置 → 配送及邮费”填写默认邮费、快递公司及分区规则。每家店按所在国家设置；规则填0为免邮，未匹配采用默认邮费，邮编优先于城市和州属。快递由商家安排。

## 商品订单

1. 顾客打开该商家的店铺链接，选商品及规格、填写地址，检查分区邮费与总额后提交。
2. 新订单为待付款，库存已预留；此时顾客购买统计不计作已付款消费。提交订单或打开付款返回网址不代表到账。
3. 商家核对自己的银行/钱包实际收到款项后，再在该订单点“确认收款”。付款截图只能辅助查找，不能代替真实到账记录。
4. 确认后订单、顾客已付款购买统计及收支账目同步；库存不重复扣。取消未付款订单恢复库存。
5. “订单管理”筛选“待发货（已付款）”，勾选最多50单，可打印配货单或收货地址标签。打印前会重新核对订单，打印不确认收款、不登记发货。地址标签不是快递公司官方面单。
6. 实际寄件/交付配送后，填写真实快递公司及运单号或配送编号。顾客在原订单页面查看发货资料，无需进入商家或平台后台。
7. 发货通知入队一次，重复保存不重复入队。邮件未配置时“等待发送”不等于已发送，顾客仍可站内查订单；服务商接受请求也不等于最终投递。
8. 仅在实际退款完成后登记退款；系统不代转账，也不假定商品已退回库存。

## 平台Pro

1. 商家在“平台订阅申请”选择平台已启用的收款方式、填写金额并提交实际付款资料。
2. 平台管理员查平台收款账户的真实到账，在独立平台后台审核实际金额、参考号及开通天数，确认后批准。
3. 提交参考号不会自行开Pro。重复批准会被拒绝；到期需重新付款审核，原试用不会反复重置。
4. 平台订阅以既有MYR收费安排为准，与各商家的商品币种、收款账户及订单账目独立。若旧Stripe自动订阅曾存在，须另外在Stripe核对取消。

## 发布结果及剩余核对

- GitHub最新CI需要整体成功，后端迁移/函数部署及网站部署不能只看build一步。源码推送不等于正式上线。
- 正式上线后，用授权的实际账号核对顾客→商家→平台流程；不要把模拟付款、收款截图或示例参考号写成真实到账证明。
- 正式数据库与图片备份、独立恢复尚需安全配置和实际执行。不要在聊天或代码提交连接串、密码、密钥和顾客资料。
